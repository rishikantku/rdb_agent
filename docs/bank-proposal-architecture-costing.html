GATE 01 Pre-LLM Scope Firewall

Deterministic intent filtering executed before LLM invocation. Non-banking questions, casual banter, creative writing, and prompt injection attempts are rejected immediately without consuming GPU compute or exposing data context.

  • Zero compute leak: Out-of-scope prompts never reach the LLM.
  • Strict categorization: In-Scope banking vs. General AI refusal.
GATE 02 Zero-Credential Air-Gap

The AI reasoning container holds zero database passwords, zero connection pools, and zero network sockets to core banking. It receives only localized schema metadata (table definitions, join graphs) and outputs text proposals.

  • No credentials stored: Hijacking the LLM yields zero database access.
  • Role-bounded schema: Only tables approved for the user's role are disclosed.
GATE 03 Deterministic AST Guardian

Every query proposed by the AI is treated as untrusted code and parsed into an Abstract Syntax Tree (AST) by SQL Guardian. Any query containing DML/DDL (DROP, ALTER, UPDATE) or multi-statement injection is blocked unconditionally.

  • Strict Read-Only: SELECT and CTE expressions only.
  • Automatic Safeguards: Hard 500-row cap and 30-second execution timeout.

Sample Institutional Banking Scenarios

1. Branch Performance, Loan Growth & Staff Efficiency Credit & Operations
Q01 Identify branches where loan portfolio growth exceeded 15% YoY while employee productivity declined for three consecutive quarters.
Very High Complexity
Business Intent: Detect operational risk early. Rapid portfolio expansion combined with declining staff productivity is a primary early warning indicator of underwriting compromises.
Tables: loans, branches, employees, employee_performance, zones, regions Mechanics: Multi-CTE · LAG() Window Functions · Trend Inversion Filter
WITH branch_loan_growth AS ( SELECT l.branch_id, CASE WHEN EXTRACT(MONTH FROM l.sanction_date) >= 4 THEN EXTRACT(YEAR FROM l.sanction_date) ELSE EXTRACT(YEAR FROM l.sanction_date) - 1 END AS fy, SUM(l.outstanding_amount) AS portfolio FROM loans l WHERE l.status = 'ACTIVE' GROUP BY l.branch_id, fy ), loan_yoy AS ( SELECT branch_id, fy, portfolio, LAG(portfolio) OVER (PARTITION BY branch_id ORDER BY fy) AS prev_portfolio, CASE WHEN LAG(portfolio) OVER (PARTITION BY branch_id ORDER BY fy) > 0 THEN ROUND((portfolio - LAG(portfolio) OVER (PARTITION BY branch_id ORDER BY fy)) * 100.0 / LAG(portfolio) OVER (PARTITION BY branch_id ORDER BY fy), 2) END AS growth_pct FROM branch_loan_growth ), branch_prod AS ( SELECT e.branch_id, ep.financial_year, ep.quarter, ROUND(AVG(ep.productivity_score), 2) AS avg_productivity, LAG(ROUND(AVG(ep.productivity_score), 2)) OVER (PARTITION BY e.branch_id ORDER BY ep.financial_year, ep.quarter) AS prev_q1_prod, LAG(ROUND(AVG(ep.productivity_score), 2), 2) OVER (PARTITION BY e.branch_id ORDER BY ep.financial_year, ep.quarter) AS prev_q2_prod FROM employee_performance ep JOIN employees e ON ep.employee_id = e.employee_id WHERE e.status = 'ACTIVE' GROUP BY e.branch_id, ep.financial_year, ep.quarter ), declining_branches AS ( SELECT branch_id FROM branch_prod WHERE avg_productivity < prev_q1_prod AND prev_q1_prod < prev_q2_prod GROUP BY branch_id ) SELECT b.branch_name, b.branch_code, s.state_name, ly.growth_pct AS loan_growth_pct, ly.portfolio FROM loan_yoy ly JOIN declining_branches db ON ly.branch_id = db.branch_id JOIN branches b ON ly.branch_id = b.branch_id JOIN zones z ON b.zone_id = z.zone_id JOIN regions r ON z.region_id = r.region_id JOIN states s ON r.state_id = s.state_id WHERE ly.growth_pct > 15 AND ly.fy = 2024 ORDER BY ly.growth_pct DESC;
Q02 Compare each branch's loan portfolio growth with the average loan portfolio growth of its region.
High Complexity
Business Intent: Regional benchmarking. Isolates systemic macro trends from branch-specific underperformance or market share gains.
Tables: loans, branches, zones, regions Mechanics: AVG() OVER (PARTITION BY region_id) · Regional Delta Calculation
WITH branch_portfolio AS ( SELECT l.branch_id, CASE WHEN EXTRACT(MONTH FROM l.sanction_date) >= 4 THEN EXTRACT(YEAR FROM l.sanction_date) ELSE EXTRACT(YEAR FROM l.sanction_date) - 1 END AS fy, SUM(l.outstanding_amount) AS portfolio FROM loans l WHERE l.status IN ('ACTIVE','NPA') GROUP BY l.branch_id, fy ), branch_growth AS ( SELECT branch_id, fy, portfolio, LAG(portfolio) OVER (PARTITION BY branch_id ORDER BY fy) AS prev_portfolio FROM branch_portfolio ), growth_pct AS ( SELECT bg.*, CASE WHEN prev_portfolio > 0 THEN ROUND((portfolio - prev_portfolio) * 100.0 / prev_portfolio, 2) END AS growth_pct FROM branch_growth bg WHERE prev_portfolio IS NOT NULL ) SELECT b.branch_name, b.branch_code, r.region_name, gp.fy, gp.growth_pct AS branch_growth, ROUND(AVG(gp.growth_pct) OVER (PARTITION BY r.region_id, gp.fy), 2) AS region_avg_growth, gp.growth_pct - ROUND(AVG(gp.growth_pct) OVER (PARTITION BY r.region_id, gp.fy), 2) AS vs_region FROM growth_pct gp JOIN branches b ON gp.branch_id = b.branch_id JOIN zones z ON b.zone_id = z.zone_id JOIN regions r ON z.region_id = r.region_id WHERE gp.fy = 2024 ORDER BY vs_region DESC LIMIT 20;
2. Customer Retention & High-Value Wealth Dynamics CASA & Wealth
Q03 Find customers whose average account balance increased by more than 20% while their transaction frequency declined.
High Complexity
Business Intent: Wealth accumulation vs. transaction velocity. Pinpoints customers parking capital without actively using payment services—prime targets for wealth products.
Tables: customers, accounts, account_balances, transactions Mechanics: Period-over-period balance comparison · Transaction count trend
WITH cust_balance AS ( SELECT a.customer_id, EXTRACT(YEAR FROM ab.balance_date) AS yr, ROUND(AVG(ab.closing_balance), 2) AS avg_balance FROM account_balances ab JOIN accounts a ON ab.account_id = a.account_id GROUP BY a.customer_id, yr ), cust_txn AS ( SELECT a.customer_id, EXTRACT(YEAR FROM t.transaction_date) AS yr, COUNT(t.transaction_id) AS txn_count FROM transactions t JOIN accounts a ON t.account_id = a.account_id WHERE t.status = 'COMPLETED' GROUP BY a.customer_id, yr ), combined AS ( SELECT cb.customer_id, cb.yr, cb.avg_balance, LAG(cb.avg_balance) OVER (PARTITION BY cb.customer_id ORDER BY cb.yr) AS prev_balance, ct.txn_count, LAG(ct.txn_count) OVER (PARTITION BY cb.customer_id ORDER BY cb.yr) AS prev_txn_count FROM cust_balance cb LEFT JOIN cust_txn ct ON cb.customer_id = ct.customer_id AND cb.yr = ct.yr ) SELECT c.customer_number, c.first_name || ' ' || c.last_name AS customer_name, co.yr, co.avg_balance, co.prev_balance, ROUND((co.avg_balance - co.prev_balance) * 100.0 / NULLIF(co.prev_balance, 0), 2) AS balance_growth_pct, co.txn_count, co.prev_txn_count FROM combined co JOIN customers c ON co.customer_id = c.customer_id WHERE co.prev_balance > 0 AND (co.avg_balance - co.prev_balance) * 100.0 / co.prev_balance > 20 AND co.txn_count < co.prev_txn_count ORDER BY balance_growth_pct DESC LIMIT 20;
Q04 Find the top 5% of customers by total relationship value within each geographic region.
Very High Complexity
Business Intent: HNI identification. Computes unified relationship value across active CASA deposits and loan advances, ranking customers within their regional peer group.
Tables: customers, accounts, loans, branches, zones, regions Mechanics: Total Relationship Value (Deposits + Advances) · PERCENT_RANK()
WITH cust_value AS ( SELECT c.customer_id, c.customer_number, c.first_name || ' ' || c.last_name AS customer_name, r.region_name, COALESCE(SUM(a.current_balance) FILTER (WHERE a.status = 'ACTIVE'), 0) + COALESCE(SUM(l.outstanding_amount) FILTER (WHERE l.status = 'ACTIVE'), 0) AS total_relationship_value FROM customers c JOIN branches b ON c.branch_id = b.branch_id JOIN zones z ON b.zone_id = z.zone_id JOIN regions r ON z.region_id = r.region_id LEFT JOIN accounts a ON a.customer_id = c.customer_id LEFT JOIN loans l ON l.customer_id = c.customer_id WHERE c.status = 'ACTIVE' GROUP BY c.customer_id, c.customer_number, c.first_name, c.last_name, r.region_name ), ranked AS ( SELECT *, PERCENT_RANK() OVER (PARTITION BY region_name ORDER BY total_relationship_value) AS pct_rank FROM cust_value WHERE total_relationship_value > 0 ) SELECT customer_number, customer_name, region_name, total_relationship_value, ROUND(pct_rank * 100, 2) AS percentile FROM ranked WHERE pct_rank >= 0.95 ORDER BY region_name, total_relationship_value DESC;
3. Staff Productivity & Departmental Compensation Integrity HR & Cost Control
Q05 Find employees whose salary is above their department average but whose performance score is below their department average.
High Complexity
Business Intent: Payroll efficiency review. Identifies cost anomalies where remuneration is decoupled from measurable departmental contribution.
Tables: employees, departments, employee_performance Mechanics: Department-level benchmark aggregation · Cross-metric anomaly join
WITH dept_avgs AS ( SELECT d.department_id, d.dept_name, ROUND(AVG(e.salary), 2) AS avg_salary, ROUND(AVG(ep.performance_score), 2) AS avg_performance FROM employees e JOIN departments d ON e.department_id = d.department_id JOIN employee_performance ep ON e.employee_id = ep.employee_id WHERE e.status = 'ACTIVE' AND ep.financial_year = 2024 AND ep.quarter = 'Q4' GROUP BY d.department_id, d.dept_name ) SELECT e.employee_number, e.first_name || ' ' || e.last_name AS full_name, e.designation, d.dept_name, e.salary, da.avg_salary AS dept_avg_salary, ep.performance_score, da.avg_performance AS dept_avg_performance FROM employees e JOIN departments d ON e.department_id = d.department_id JOIN dept_avgs da ON d.department_id = da.department_id JOIN employee_performance ep ON e.employee_id = ep.employee_id AND ep.financial_year = 2024 AND ep.quarter = 'Q4' WHERE e.status = 'ACTIVE' AND e.salary > da.avg_salary AND ep.performance_score < da.avg_performance ORDER BY (e.salary - da.avg_salary) DESC LIMIT 20;
Q06 Identify departments where employee attrition increased for three consecutive quarters.
Very High Complexity
Business Intent: Attrition acceleration. Pinpoints structural workplace issues or retention vulnerabilities before critical institutional knowledge is lost.
Tables: employees, departments Mechanics: Quarter serialization · Consecutive LAG comparison
WITH quarterly_attrition AS ( SELECT e.department_id, CASE WHEN EXTRACT(MONTH FROM e.exit_date) >= 4 THEN EXTRACT(YEAR FROM e.exit_date) ELSE EXTRACT(YEAR FROM e.exit_date) - 1 END AS fy, CASE WHEN EXTRACT(MONTH FROM e.exit_date) IN (4,5,6) THEN 'Q1' WHEN EXTRACT(MONTH FROM e.exit_date) IN (7,8,9) THEN 'Q2' WHEN EXTRACT(MONTH FROM e.exit_date) IN (10,11,12) THEN 'Q3' ELSE 'Q4' END AS quarter, COUNT(*) AS attrition_count FROM employees e WHERE e.status IN ('RESIGNED', 'TERMINATED') AND e.exit_date IS NOT NULL GROUP BY e.department_id, fy, quarter ), ranked AS ( SELECT *, LAG(attrition_count, 1) OVER (PARTITION BY department_id ORDER BY fy, quarter) AS prev_q1, LAG(attrition_count, 2) OVER (PARTITION BY department_id ORDER BY fy, quarter) AS prev_q2 FROM quarterly_attrition ) SELECT d.dept_name, r.fy, r.quarter, r.attrition_count, r.prev_q1 AS previous_quarter, r.prev_q2 AS two_quarters_ago FROM ranked r JOIN departments d ON r.department_id = d.department_id WHERE r.attrition_count > r.prev_q1 AND r.prev_q1 > r.prev_q2 AND r.prev_q2 IS NOT NULL ORDER BY r.attrition_count DESC;
4. Query Guardrail Enforcement Examples (Refusal Mechanics) Safety Controls

The table below demonstrates how the Query Scope Guardrail and SQL Guardian respond to out-of-scope, conversational, or malicious user requests:

✗ BLOCKED · OUT_OF_SCOPE
"What is the capital of India?"
Reason: General Knowledge question. Refused at Gate 1 before calling the LLM. System responds: "RDB Agent answers questions using authorized banking database tables. This general knowledge question cannot be answered from your banking records."
✗ BLOCKED · OUT_OF_SCOPE
"Write a Python script to sort a binary search tree."
Reason: General Programming / Code Generation. Refused at Gate 1. Prevents general chatbot usage and enforces strict institutional remit.
✗ BLOCKED · SECURITY CRITICAL
"DROP TABLE employees; SELECT * FROM employees;"
Reason: Destructive Statement / Injection Attempt. Blocked at Gate 3 by SQL Guardian AST validator: "DESTRUCTIVE_OPERATION: DROP operations are not permitted. Only SELECT queries are allowed."
✓ ALLOWED · IN_SCOPE
"Show top 10 branches by employee count and average salary in Jharkhand."
Reason: Matches banking schema objects (employees, branches, states). Permitted through all 3 gates and executed with safety limit (500 rows).
04 · Governance, Data Privacy & Regulatory Alignment

Compliance with RBI & Banking IT Security Norms

RDB Agent has been engineered from the ground up to address the stringent regulatory requirements mandated by the Reserve Bank of India (RBI Cyber Security Framework, Digital Banking Unit guidelines, and Master Directions).

Regulatory / Security Requirement Conventional Public AI (ChatGPT / Copilot) RDB Agent Governed Architecture
Data Residency & Sovereignty Data transmitted to US cloud servers (Azure/OpenAI). Violates domestic residency. 100% On-Premise: Operates entirely inside the bank's data center behind air-gapped firewalls.
Database Credential Exposure Agents require direct read/write database connection strings or ODBC drivers. Zero DB Credentials on AI: The LLM container has no database network route or password.
Risk of Accidental Data Mutation Prompt hallucination can issue UPDATE or DELETE statements directly to data. AST Deterministic Guard: Every statement is parsed; write operations are architecturally impossible.
Scope Creep & Hallucination Answers general knowledge, personal advice, and unverified data opinions. Pre-LLM Scope Firewall: Categorically refuses all non-bank conversational drift.
Regulatory Audit Trail Black-box conversational history stored externally. Non-reproducible. Complete Audit Logging: Full prompt, generated SQL, execution metrics, and user remits stored locally.
Exfiltration Protection Entire tables can be scraped and returned in conversational output. Enforced Row Caps: Hard 500-row limit and 30-second query timeout enforced at parser level.
